## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The plugin (task-197, task-198) gets its editor: orb-ui's panel inside the host's plugin window, as task-185's final summary decides (read it first). The user reviews the visual result before merge.

- **Embedding:** nice-plug's `nice-plug-egui` adapter (egui 0.37, as orb-ui; egui-baseview with the `wgpu` feature). Share the panel code with orb-ui (factor out what is eframe-specific) rather than copy it.
- **The window is the menu bar and the panel** (changed by the user, 2026-11-16): the standalone app's menu strip (menu.rs `menu_bar`, MENU_H) on top, unscaled exactly as in the standalone app; only the panel scales. The window is panel height + strip height and nothing else: no metallic filler background around the panel.
- **Panel changes in the plugin:** hidden: the pattern/song switch, the loop switch and range, Rewind, Record, File > Save. The tempo display stays, read-only (its up/down buttons hidden), showing the tempo orb plays at (the host's, or the song's when the host reports none). orb's Play/Stop is the mode switch (task-198). The transport's display box whose song position / loop readouts are hidden shows the host position as bar.beat, as the standalone shows the song position; in note mode or with no host position it shows what the standalone shows when stopped (or blank), documented (the user, 2026-11-16). Everything else works as in the standalone app (knobs, patterns, mixer, effects, File > New/Open/Info, Mods menu, Help).
- **Menus:** the standalone's egui-drawn menu strip (no native menu bar). File dialogs (Open, mod loading) must work inside hosts (check rfd from a plugin window; fall back to something safe if it does not).
- **LEDs:** MIDI LED on incoming host MIDI; Sync LED lit while orb follows the host position (task-198's snapshot flags).
- **Sizing** (changed by the user, 2026-11-16), saved in the plugin state: the rule height = width * (PANEL_H/PANEL_W) + strip height.
  1. host-driven resizing: no fixed aspect ratio; the rule is enforced through the size-adjust hooks (CLAP `gui.adjust_size` with the aspect-ratio hint off, VST3 `IPlugView::checkSizeConstraint`), and `EditorHandle::set_size()` applies the host's size;
  2. the plugin's own resize corner, invisible: only the mouse cursor changes over it; dragging asks the host to resize (VST3 `IPlugFrame::resizeView`, CLAP `gui.request_resize`, through nice-plug) to exact sizes of the rule.
  No zoom presets.
- **No keyboard shortcuts at all** (the user, 2026-11-16; hosts take keys from plugin windows, and Phoscyon 2 and ABL3 advertise none): no menu accelerators shown or handled, no keyboard modes / computer-keyboard step programming or pattern keys, no key handling; the editor does not grab keyboard focus where avoidable, so the host keeps its keys. Mouse gestures (double-click reset, drags, modifier-drags) stay. The standalone app is unchanged.
